# Flowbiz Onsite SDK for Android — Data Disclosure

This document discloses every data type the SDK collects, transmits and
stores, so integrators can complete Google Play's **Data safety** form
accurately (SPEC §12). It is written against the actual implementation
(`br.com.flowbiz:onsite-sdk` 0.1.0); the iOS equivalent is the bundled
`PrivacyInfo.xcprivacy` privacy manifest.

Registration of the SDK in Google's **SDK Console** (Play SDK Index) is
planned once the SDK is public; until then this document is the integrator's
source of truth.

## Where data goes

All collected data is sent exclusively to the Flowbiz collector configured
at initialization: `FlowbizConfig.collectorUrl`, default
`https://collector.mailbiz.one`, endpoint `POST /collect`, HTTPS only. The
SDK contacts no other endpoint, embeds no third-party SDKs, and shows no
ads. The collector infrastructure additionally derives the client **IP
address** and **User-Agent** from the HTTP request itself (server-side, not
sent by the SDK).

Data is collected **only for events the host app explicitly tracks** (plus
the automatic `page.ping` heartbeat while the app is foregrounded and the
SDK is enabled). `Flowbiz.setEnabled(false)` stops all collection and
network traffic, persistently, until re-enabled — this is the hook for
LGPD/GDPR consent gating.

## Data types collected (transmitted to the collector)

| Data type | Source | Wire location | Notes |
|---|---|---|---|
| Email address | `accountLogin` / `accountSync` events | `data.user.email`; also stored locally | Provided by the host app |
| Phone number | `accountLogin` / `accountSync` (optional field) | `data.user.phone` | Only if the host app supplies it |
| Name | `accountLogin` / `accountSync` (optional field) | `data.user.name` | Only if the host app supplies it |
| Subscription/plan name | `accountLogin` / `accountSync` (optional field) | `data.user.plan` | Only if the host app supplies it |
| Account creation date | `accountLogin` / `accountSync` (optional field) | `data.user.created_at` | Only if the host app supplies it |
| User ID (account identifier) | `accountLogin` / `accountSync` | `data.user.user_id`, then `identity.user_id` on every subsequent event until `logout()` | |
| Anonymous device/install ID | Generated by the SDK (random UUID v4 on first init) | `identity.anonymous_id` on every event | Not a hardware/advertising ID; resets on app uninstall |
| Session ID + visit count | Generated by the SDK | `identity.session_id`, `identity.visit_count` | 30-min inactivity rotation |
| Purchase history | `cartSync`, `addToCart`, `cartItemUpdate`, `checkoutStep`, `orderComplete`, `orderCancel` | `data.cart` / `data.order` / `data.products` | Cart/order contents, totals, coupons, payment method types+amounts |
| Delivery address | `cartSync` / `orderComplete` optional `deliveryAddress`; `cartSetPostalCode` | `data.*.delivery_address`, `data.postal_code` | Only if the host app supplies it |
| Product interaction | `pageView`, `productView`, `cartSetCoupon`, automatic `page.ping` heartbeat | `data.page` / `data.product` etc. | Screen names, product/SKU views |
| Push token (FCM registration token) | `setPushToken` / `removePushToken` / `logout()` | `data.token` of `push.token.sync` / `push.token.remove` | Relayed so the Flowbiz backend can message the device |
| Device/app context | Collected by the SDK | `context.language`, `context.screen` (resolution), `timings.timezone` (UTC offset), platform + SDK version | No hardware identifiers |
| IP address / User-Agent | Not sent by the SDK | Derived server-side from HTTP headers at the collector | Standard for any HTTPS request |

The SDK never accesses: advertising ID (AAID), Android ID, IMEI, location
APIs, contacts, or any permission-gated data. Its manifest merges only the
normal-level `ACCESS_NETWORK_STATE` permission; the host app must hold
`INTERNET` (virtually always already declared) for delivery to work.

## Data stored locally on the device

| Storage | Location | Contents | Cleared by |
|---|---|---|---|
| SharedPreferences `flowbiz_onsite_<appId>` | App-private storage | `anonymous_id`; `user_id` + `email` (after account events); `session_id`, `visit_count`, `last_activity_wall_ms`; `enabled` opt-out flag; `push_token` (last registered token); `dedup_digest_<event>` / `dedup_at_<event>` (SHA-256 digests of last payloads — digests, not payloads) | `logout()` clears user identity + push token; uninstall clears all |
| Event queue `files/flowbiz_onsite/<appId>/queue.jsonl` | App-private storage | Pending event envelopes (may contain the PII above) until successfully delivered; capped at 1000 events, compacted after flushes | Successful delivery; uninstall |

All storage is app-private (`MODE_PRIVATE` / app files dir); nothing is
written to shared/external storage. Data is retained locally only as
described above; server-side retention is governed by the Flowbiz platform's
data-retention policy (outside SDK scope — integrators should reference the
Flowbiz DPA).

## Google Play Data safety form — row-by-row mapping

Declare the following for the SDK's collection (merge with your app's own
declarations). "Collected" applies only if your app actually tracks the
corresponding events; rows marked *conditional* apply only when your app
supplies that field.

| Play form category → data type | Collected? | Shared? | Processed ephemerally? | Required or optional | Purposes to declare |
|---|---|---|---|---|---|
| Personal info → Email address | Yes, if you track account events | No¹ | No | Optional (only on login/sync) | Analytics, App functionality |
| Personal info → Name | *Conditional* (account events with `name`) | No¹ | No | Optional | Analytics, App functionality |
| Personal info → Phone number | *Conditional* (account events with `phone`) | No¹ | No | Optional | Analytics, App functionality |
| Personal info → User IDs | Yes (account `user_id`; SDK `anonymous_id`) | No¹ | No | Required for SDK function (`anonymous_id`) | Analytics, App functionality |
| Personal info → Address | *Conditional* (`deliveryAddress` / postal code on cart/order events) | No¹ | No | Optional | Analytics, App functionality |
| Financial info → Purchase history | Yes, if you track cart/checkout/order events | No¹ | No | Optional | Analytics, App functionality |
| App activity → In-app actions (page views, taps, etc.) | Yes (`pageView`, `productView`, heartbeat, checkout steps) | No¹ | No | Optional | Analytics, App functionality |
| App info and performance | No | — | — | — | — |
| Device or other IDs | No² | — | — | — | — |
| Location | No (no location APIs; a user-typed delivery address is declared under Personal info → Address) | — | — | — | — |

¹ "Shared" in Play's definition means transfer to a *third party*. The SDK
transmits data to the Flowbiz collector acting as the app developer's
service provider (processor). If your legal assessment classifies Flowbiz
as an independent third party for your app, mark these rows as shared with
purpose Analytics — confirm with your DPO.

² Play's "Device or other IDs" targets identifiers like the AAID or
hardware IDs. The SDK's `anonymous_id` is a self-generated, app-scoped
random UUID, conventionally declared under "User IDs" (pseudonymous
identifier). If your reviewer prefers the conservative reading, also mark
"Device or other IDs" as collected.

Additional form answers relevant to the SDK:

- **Is all of the user data collected by your app encrypted in transit?**
  Yes — the SDK enforces HTTPS (`collectorUrl` must be `https://`).
- **Do you provide a way for users to request that their data is deleted?**
  Host-app responsibility; the SDK offers `logout()` (clears local
  identity) and `setEnabled(false)` (stops collection). Server-side
  deletion requests go through the Flowbiz platform.
- **Data collected is user-initiated**: all business events are explicit
  host-app `track()` calls; only the foreground heartbeat is automatic.

## Debug logging

With `debug = true` the SDK logs diagnostics via `Log.d("FlowbizOnsite", …)`.
Logs never contain PII: they carry wire event names, counts, HTTP status
codes and exception class names — never event payload strings, user fields
or push tokens (SPEC §12; pinned by `DebugLogRedactionTest`).
